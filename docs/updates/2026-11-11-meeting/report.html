The headline change: the evidence reviewer used to see only admitted facts. It now receives the actual argument/critique/score trace from the debate stages — so it can flag a gap the critics exposed, not only one missing from the raw fact list.本次主要修正：證據審查者原本只看到已接納的事實，現在也會收到辯論階段的論點、批評與評分紀錄，因此可以根據批評指出的重要問題安排後續研究。

What we adapted, role by role逐角色的調整與實作

Nine actor cards (index) cover every role in the workflow, each with task, inputs/outputs, tools, stop rules and actual code pointer. Only the LLM stages below are "agents" in a model-call sense; the gateway and final aggregator are deterministic code.

九份角色／模組規格均列出任務、輸入輸出、工具、停止規則與實際程式位置。只有需要呼叫語言模型的階段，才是模型意義下的 agent；驗證閘道與最終彙整器是確定性程式。

Underneath, a separate real fix: research-cache keys now hash the actual prompt bodies (plus the vendor files they call), not only a manually-typed version string — so editing a prompt can no longer silently reuse a stale cached answer.

另一項實際修正是快取版本：研究快取鍵現在包含 prompt 正文及其依賴的原版程式內容雜湊，不只依賴手動填寫的版本名稱。因此修改 prompt 後，不會悄悄重用舊版本的快取答案。

The second pass first built a source-completion ledger for 138 non-YES companies from existing cache only (0 new calls for that step). It then made 4 Crunchbase API calls across 3 companies to check request/response structure, with a local 30-call ceiling for this batch. The 13 pending leads are mostly previously known; 0 new positives were accepted. Twelve share the same 2026-01-01/no-amount shape, which neither proves a placeholder convention nor independently confirms twelve dates. This is only the first batch, not a completed second pass or proof that 90% is impossible.

第二輪先利用既有快取，為 138 家尚未確立公開披露的公司建立來源檢查清單；此步驟沒有新增呼叫。之後針對 3 家公司進行 4 次 Crunchbase API 呼叫，以檢查請求與回傳結構，本批次自設執行上限為 30 次。整理出的 13 條待核驗線索，多數先前已知，沒有新增可接納的正例。其中 12 條具有相同的 2026-01-01、無金額紀錄形態，但這不能證明是佔位日期，也不能當成 12 次獨立的日期確認。本次只是第二輪的第一批，並未完成整輪檢查，也未證明 90% 的目標不可能達到。

Supplementary status availability (228/240 = 95%) is a directory-reported status proxy, not confirmed historical operation. Twenty-one URLs were checked on three actual days (Nov 7, 10, 11): 19 continued access failures, and 2 HTTP 200s showing unrelated content or a parked domain, not recovered operations. These November 2026 observations cannot establish April 2026 status.

狀態補充 Y 的 228/240（95%），代表有資料庫目錄狀態可供參考，不是歷史營運狀態已獲證實。本次對 21 個網址完成三個實際日期的檢查：11 月 7、10、11 日。其中 19 個持續存取失敗；另有 2 個回傳 HTTP 200，但分別是無關內容與網域停放頁，不能視為公司恢復營運。這些是 2026 年 11 月的觀察，不能據此確定公司在 2026 年 4 月的狀態。
